name: long-conversation-canvas
description: 在用户要求查看或组织 Codex 长对话画布时使用，围绕指定主对话展示任务分支和上下文来源。
---

使用插件工具，不启动独立桌面应用。先使用 canvas_read 核对主对话，再使用 canvas_render 展示嵌入画布。需要查看已有聊天时使用 codex_threads 和 codex_thread_read。插件支持人工创建独立子聊天、分叉、续聊、取消、工程检查和持久复核；动作是否成功，以实际运行记录、原文及验证证据为准。

外层画布保留任务树总览，双击聚焦单个聊天。主干、树层级、重要性和授权档位分别维护；重要性提高不自动移动到主干。子任务只带固定主干、明确任务及选定原文/成果，完成后先交直接父任务，不向所有兄弟反复复制完整历史。

若当前插件派发的轮次明确提供 canvas_propose 的 projectId、nodeId、sourceRunId、authorization，可在当前授权范围内用此工具提交子任务或续聊提案。凭证仅本轮有效，只用于工具调用，不写入文件、成果或回复，不借用其他轮次凭证。工具缺失时报告建议，不能声称已派发。模型不能通过 app-only 工具授予权限、审批自己的提案或代替用户回应宿主工具审批。

授权档位为逐项复核、任务内放权、分支内放权、范围内自主。前两档模型提案等待人工；分支档必须提供已批准 planItemId，任务正文逐字匹配计划；自主档仍须满足范围、深度、未完成子任务数、累计动作额度及有效期。超限、扩大到全项目、改归属或提取专题转人工。来源轮次完成后队列才判断派发。人工暂停会阻止子树新派发，停止请求须等远端终态；结果未知只核查原请求，不换命令 ID 重发。

代码任务的约定路径通过工程契约、实际 Git 基线、差异及串行门禁约束，执行权限仍为项目工作区，不宣称目录级系统隔离。临时借用范围保留父任务登记，归还后父任务恢复。阶段摘要不等于宿主原生压缩，不对摘要继续连续压缩；未知历史如实标记。

原始用户约束、AI 建议和已确认决定应区分。主对话缺失、压缩历史未知、读取失败时显示实际状态，不猜测、不补造上下文。模型回复完成不等于任务完成。节点选择只传必要信息；不把完整历史反复写入当前模型上下文。

嵌入 UI 在当前宿主实际渲染才算完成。工具结果、插件安装和资源读取不证明 UI 成功。
